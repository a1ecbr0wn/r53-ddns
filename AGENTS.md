# AGENTS.md

## Project Overview

`r53-ddns` is a Rust CLI tool that keeps an Amazon Route 53 DNS record in sync
with the current external IP address of a network. It is a single binary with
no server component. The two source files are `src/main.rs` and `src/cli.rs`.

## Build & Test

```sh
cargo build          # debug build
cargo test           # run tests
cargo clippy         # lint (CI runs this as a required check)
cargo fmt --check    # format check (CI blocks on this)
```

CI enforces `--deny warnings` via `RUSTFLAGS`, so all clippy warnings must be
resolved before merging. Format is checked with `rustfmt` on every push.

## CI Targets

The build matrix covers:

- Linux: `x86_64`, `armv7-gnueabihf`, `armv7-musleabihf`, `aarch64`
- macOS: `x86_64-apple-darwin`, `aarch64-apple-darwin`

Cross-compilation uses the `cross` crate. Avoid adding dependencies that break
cross-compilation or require `cmake` at build time — the snap build on `armhf`
does not have it (see the `reqwest` comment in `Cargo.toml`).

## Code Conventions

- Two source files only: `src/main.rs` (logic) and `src/cli.rs` (clap args).
- Errors are logged via `log`/`log4rs`. Use `warn!` for actionable errors and
  `info!` for state that is only relevant with `-v`. Use `debug!` for
  diagnostics only relevant with `-D`.
- Alert hook calls use JSON: `{ "type": "<type>", ... }`. Existing types are
  `error`, `ip-change`, and `ip-new`. Keep new alert payloads consistent.
- AWS errors must be parsed from the XML response body — do not forward raw
  `RusotoError` display output to the user. Use `format_aws_error()`.
- Do not add XML or JSON parsing dependencies; use string operations instead.

## Dependencies

- AWS SDK: `rusoto_core` + `rusoto_route53` with the `rustls` feature (not the
  default TLS, for cross-compile compatibility).
- HTTP: `reqwest` with `native-tls-vendored` and `http2` features, no defaults.
- Do not switch TLS backends without checking the snap/armhf build.

## Release Process

Releases are driven by git tags (see `.github/workflows/tag.yml` and
`release.yml`). The version in `Cargo.toml` must match the tag. Changelog is
generated by `git-cliff` using `cliff.toml`.
